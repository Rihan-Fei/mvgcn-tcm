# MVGCN — prior-anchored multi-view graph convolution for TCM herb recommendation

Reference implementation and evaluation protocol for the paper

> **MVGCN: Prior-Anchored Multi-View Graph Convolution for TCM Herb
> Recommendation**
> (submitted to *Knowledge-Based Systems*)

The model is named `SMGCN_MVANA` in the code — it is a faithful PyTorch port of the
TensorFlow implementation used in the authors' earlier work — and **MVGCN** in the
paper. The multi-view encoder, including the three relational views and the
cross-layer fusion (`SANA`), follows SMGCN (Jin et al., ICDE 2020) and is used here
as a fixed backbone; the contribution of the paper is the frozen empirical-Bayes
anchor, the twenty-seed protocol and the component decomposition.
Everything needed to reproduce the reported numbers is in this repository;
the raw per-seed result files are not, since they are regenerated by the commands
below (see [Result files](#result-files)).

---

## 1. What the method is

MVGCN couples two components:

* **A graph branch.** Two message-passing channels over the symptom–herb graph,
  each with a different DropNode mask, row-wise L2 normalisation after every layer,
  symptom–symptom and herb–herb residual projections, a gated cross-layer fusion of
  the last two layers (SANA, as in SMGCN), and masked key–value attention over the
  symptom set (records are variable length: 1–16 symptoms, mean 1.5).
* **A frozen empirical-Bayes prior.** P(herb | symptom) estimated from the training
  prescriptions only, shrunk towards the marginal herb frequency, stored as a matrix
  that the optimiser never updates. Its score enters the logit through a gate
  initialised at 0.01, so training starts from the empirical conditional
  distribution and the graph branch can only refine it.

The training target is a ranking-aware hard-negative objective: frequency-weighted
binary cross-entropy over the K=50 hardest negatives in each batch. Baselines are
trained with frequency-weighted BCE, the objective under which they are usually
reported, so the contribution of the target and the contribution of the prior are
separated rather than conflated.

## 2. Requirements

Python ≥ 3.9 with PyTorch. The reported runs used:

| package | version |
|---|---|
| torch | 2.14.0 (CUDA 13.0 build; CPU also works) |
| numpy | 2.5.5 |
| scipy | any recent (only for `paired_compare.py`) |
| matplotlib | any recent (only for `plot_joint_hp.py`) |

```bash
pip install -r requirements.txt
```

A single seed of the full model takes about 700 s on one laptop GPU (RTX 5060,
8.5 GB); MF takes 95 s, LightGCN 208 s, NGCF 133 s. CPU training is possible but
roughly an order of magnitude slower — use `--device cpu` and a small `--epochs`
for a smoke test.

## 3. Data

The corpus is **SDPR Herb**, collected and released by Yue et al. together with the
SDPR model (*IEEE J. Biomed. Health Inform.* 29(5):3736–3749, 2025,
doi:10.1109/JBHI.2025.3525507). It is third-party data; this repository claims no
ownership of it and does not redistribute it.

```bash
git clone --depth 1 https://github.com/ywjawmw/SDPR /tmp/SDPR
mkdir -p Data/SDPR_Herb
cp /tmp/SDPR/data/Herb/*_id.txt Data/SDPR_Herb/
python baselines/prepare_sdpr_data.py      # writes train.txt / valid.txt / test.txt
```

After preparation the loader expects `Data/SDPR_Herb/{train.txt,test.txt}`, one
record per line:

```
<symptom_id> <symptom_id> ... <TAB> <herb_id> <herb_id> ...
```

Corpus size: **26,360 prescriptions**, 360 symptom types, 753 herb types, no empty
records. The official partitions are 21,755 training and 3,443 test prescriptions
(the 1,162 official validation records are not used separately). The protocol holds
out 10% of `train.txt` with the fixed split seed 2021 — 2,175 records for early
stopping and model selection, 19,580 for parameter updates — so the test partition
is byte-identical to the one used by the SDPR paper and the two are directly
comparable.

Set `MVANA_DATA_ROOT` to keep the corpus elsewhere; `MVANA_RESULT_DIR` likewise
redirects the result directory.

## 4. Quick start

```bash
cd baselines

# one seed of the full model, 1600 epochs (default configuration)
python run_baselines_v2.py --dataset sdpr --model SMGCN_MVANA \
    --sana_calib layer --sana_alpha 0.2 --sz_c 2 --d_kv 64 --mask_rate 0.2 \
    --mfm MFM --direct_shrink 1.0 --direct_gate_init 0.01 --l2_target e0 \
    --dim 64 --lr 1e-3 --reg 1e-4 --batch 1024 --epochs 1600 \
    --eval_every 50 --patience 10 --split_seed 2021 --self_loop 1 \
    --views ss,hh --weighting invfreq_pos --loss hard_bce --topk 50 \
    --seeds 1 --seed_start 0 --device cuda --tag demo
```

`python run_baselines_v2.py --help` lists every option; `--model` accepts a single
model or a preset group (`basic`, `comparison`, `all`). Available models:
`Popularity`, `MF`, `MLP`, `NGCF`, `LightGCN`, `GAT`, `SMGCN`, `MVGCNLite`,
`MVGCN`, `SMGCN_MVANA`.

Two self-contained checks that need no data file (synthetic tensors only):

```bash
python test_basic_models.py     # MLP / NGCF / SMGCN forward + short training
python test_mvgcn_flow.py       # MVGCN graph construction, forward, backward
```

## 5. Reproducing the paper

All commands run from `baselines/`. Seeds are `0..N-1`; the same seed always
produces the same numbers on the same machine, and runs resume from the existing
`*_runs.jsonl`.

### 5.1 Main comparison (Table 2, eleven models × 20 seeds)

Baselines use frequency-weighted BCE for up to 4,000 epochs; MVGCN uses the
hard-negative objective for up to 1,600 epochs. Everything else is shared.

```bash
COMMON="--dataset sdpr --dim 64 --lr 1e-3 --reg 1e-4 --batch 1024 \
        --eval_every 50 --patience 10 --split_seed 2021 --self_loop 1 \
        --weighting invfreq_pos --seeds 20 --seed_start 0 --device cuda"

for M in Popularity MF MLP NGCF LightGCN GAT SMGCN MVGCNLite MVGCN; do
  python run_baselines_v2.py $COMMON --model $M --epochs 4000 --loss bce --tag U_sdpr2
done

python run_baselines_v2.py $COMMON --model SMGCN_MVANA --epochs 1600 \
  --loss hard_bce --topk 50 --tag U_sdpr2
```

### 5.2 Baselines under the ranking objective (§5.4)

```bash
python run_baselines_v2.py $COMMON --model MF   --epochs 1600 --loss hard_bce --topk 50 --tag hb20_mf
python run_baselines_v2.py $COMMON --model NGCF --epochs 1600 --loss hard_bce --topk 50 --tag hb20_ngcf
```

### 5.3 Ablation and univariate sensitivity (Table 3 and Table 5, 3 seeds each)

The full configuration is the `BASE` array at the top of `run_queue_all.sh`; each
queue line overrides one component.

```bash
QFILE=queues/ablation_univariate.txt bash run_queue_all.sh 0 1
```

### 5.4 Joint grid over the fusion weight and the prior shrinkage (Table 6, Figure 2)

```bash
QFILE=queues/joint_grid.txt bash run_queue_all.sh 0 1
```

Set the second argument to the number of parallel workers — **two is the safe
limit** on a single 8.5 GB GPU; three or more start thrashing on memory.

### 5.5 Tables and figures from the result files

```bash
python make_three_tables.py          # main / ablation / sensitivity tables (markdown)
python make_table_all_metrics.py     # nine metrics P,R,F1 @ 5,10,20 of Table 2
python ablation_paired.py            # per-seed paired t-tests for every ablation row
python make_table_hb_vs_bce.py       # BCE vs hard-negative comparison table
python md_tables_to_tex.py tables.md tables.tex   # markdown -> booktabs LaTeX
python plot_joint_hp.py              # Figure 2 (contours) and Figure 3 (marginals)

python paired_compare.py MF_U_sdpr2 SMGCN_MVANA_U_sdpr2   # ad-hoc paired test
```

## 6. Result files

Every run appends one JSON object per seed to

```
results/v2_<dataset>_<model>_<tag>_runs.jsonl
```

and writes an aggregate `..._summary.json` (means, standard deviations, the exact
`args`, and a configuration hash). Fields per record include `P@5`, `P@10`, `P@20`,
`R@5`, `R@10`, `R@20`, `F1@5`, `F1@10`, `F1@20`, `_seed`, `_best_epoch`,
`_train_time_s` and the validation trajectory. Because records are appended and the
configuration hash guards against mixing, an interrupted run resumes where it
stopped and two processes cannot silently corrupt one file.

## 7. Implementation notes

* `SMGCN_MVANA` fixes the number of propagation layers at **L = 2** with widths
  128 and 256, mirroring the TensorFlow original (`weight_size = [128, 256]`);
  `--layers` affects only the other models.
* `--l2_target e0` adds the penalty to the layer-zero embeddings, not to the
  propagated ones. Without this, symmetric normalisation shrinks the effective
  penalty of a deep model to a fraction of that of a shallow one, and the models are
  no longer comparable at a shared `--reg`.
* `--loss hard_bce` with `--topk K` is the ranking-aware objective of the paper;
  `--loss bce` is the frequency-weighted baseline objective.
* `--direct_residual` + `--freeze_direct` enable the frozen prior and its additive
  residual path; `--direct_shrink` is the empirical-Bayes shrinkage coefficient and
  `--sana_alpha` the cross-layer fusion weight.
* Views (`--views ss,hh`) and the prior are rebuilt from the training partition
  only, after the internal split, so no validation or test record leaks into them.
* Metrics are computed on the full test partition, truncated at 20, with ties broken
  by item id; `K = 5, 10, 20` are reported because P@5 and R@20 respond to different
  parts of the model.
